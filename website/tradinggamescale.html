Trading Game — Scaling Architecture
Proposal for growing the candidate universe from 60 to ~1,500 companies
Proposed · not implemented Living document — edit this page directly whenever the design changes. Nothing on this page is committed code yet; ActorCriticPolicy in policy.jl still uses full self-attention. Numbers below marked "measured" come from a real script run against this machine's GPU; numbers marked "projected" are estimates for the not-yet-built design.
Why the current design won't reach 1,500
ActorCriticPolicy's MultiHeadAttention runs full self-attention across every candidate — all N stocks plus the portfolio token attend to each other. That's an N×N cost. At N=60 (today) that's cheap. At N=1,500 it isn't: measured directly on this machine (RTX 5060 Ti, 16.7 GB VRAM) by running ActorCriticPolicy's actual forward + backward + optimizer step at each size below.

Isolating the attention layer alone confirms it's the driver: at N=61 it uses 17 MB (batch 32); at N=1,501 the same layer alone uses 6.06 GB at batch 32 — a ~360× jump for a ~25× increase in N, consistent with N² scaling. Batch size can't rescue this the way it did for StockSwingPredictor, because that model's cross-attention is one query against N peers (O(N)) — ActorCriticPolicy's is every candidate against every other (O(N²)).
Current vs. proposed attention pattern
Current — full self-attention O(N²)
Every candidate attends to every other candidate directly
Proposed — shared summary tokens O(N·K)
Each candidate cross-attends only to K shared tokens (K≈2, fixed)
Each candidate still gets a joint, context-aware decision — it just gets that context from a small set of shared summary tokens instead of from every other candidate individually. This mirrors StockSwingPredictor's existing cross-attention pattern (one query against N peers), just inverted: here every candidate is a query, and the peer set is replaced by a small, fixed K.

Open questions
K, the number of summary tokens. Starting guess: 2 (a mean-pooled "market pulse" + the existing macro/portfolio token). More tokens (e.g. per-sector pools) trade a bit more O(N·K) cost for richer shared context.
Pooling method. Plain mean-pool is O(N) and simplest; a lightweight attention-pool (learned query, N keys — still O(N), same shape as StockSwingPredictor's existing cross-attention) may capture more signal at a small extra cost.
GPU wiring is a separate, still-needed piece of work. ppo.jl/train.jl run entirely on CPU today (a deliberate Stage 3 scoping decision) — the measurements above test the network in isolation, not the full rollout+update loop.
assemble_observation is a separate CPU bottleneck. It's a per-candidate Julia loop, called once per environment step — not addressed by any of the above. Worth profiling once N grows.

2026-09-29
Initial proposal
Measured that the current full-self-attention ActorCriticPolicy OOMs on this machine's 16.7 GB GPU between batch 8 and 16 at N=1,500. Proposed replacing candidate-to-candidate self-attention with candidate-to-summary-token cross-attention (O(N·K) instead of O(N²)) to unlock GPU-scale batch sizes at 1,500 candidates, mirroring StockSwingPredictor's existing cross-attention pattern.
