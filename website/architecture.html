Current network architecture — game v3
What ActorCriticPolicy is today for --game-version 3 (BSE, 15-minute bars): 29,129 parameters. The macro GRU and the news inputs are switched off in v3 (the code stays; other versions still use them), and there are no separate cash or portfolio tokens: the seven portfolio scalars (cash state and free holding slots included) are repeated beside every stock and enter the same fusion layer. The rules that refuse a move are visible to the network: four per-stock legality inputs (rebuy cooldown left, affordability, position-cap headroom, sellable) and the free-slot count, and an auxiliary legality head is trained to predict why a buy would be refused. Every stock goes through the same weights, so the model has no notion of which stock is which. Shapes below are per decision step; N is the candidate count and attention runs over N tokens.
The ReLU layer
v3 has one ReLU layer, the fusion layer in front of attention (the separate portfolio and cash encoders are gone). It is a fully connected layer: every input feeds every output through its own weight (each line below is one weight), each output unit adds a bias, and a ReLU max(0, x) keeps positive values and zeroes the rest. Each stock's 85 inputs are its own 70 returns and 8 state features (four of them legality inputs) plus the 7 portfolio scalars, which are the same for every stock at a given bar. The same weights serve every stock. The sketch draws only a handful of nodes — the real widths are in the caption — but the lines are the real connectivity.
Fusion — one token per stock 85 → 64 · 5,504
70 returns + 8 state features (held · P&L · hold left · snapshot · cooldown · affordability · cap headroom · sellable) + 7 portfolio scalars; 85 × 64 = 5,440 weights + 64 biases
Compared with the attention graph below, this layer never looks sideways: a unit in the output only sees its own stock's inputs (and the shared portfolio numbers), so its cost grows with the number of stocks rather than with its square.
Attention pattern — game v3 (current)
v3 — full self-attention over the stocks O(N²)
Every candidate attends to every other candidate directly. There is no cash or portfolio token: the seven portfolio numbers are already inside each stock's fusion input
In game v3 attention runs over the N stock tokens alone (the output of the 85→64 fusion layer, one token per candidate). The critic reads the mean of the attended tokens plus the seven portfolio scalars, and the auxiliary legality head reads the same attended tokens. The cost is still the N² pairwise term that the capacity calculator on the TG Scaling page fits.
Forecaster — game v4 (TradingGame.Forecaster, trained by scripts/forecaster/train_minute_forecaster.jl)
A supervised next-minute predictor on 1-minute BSE closes, with no news, macro or portfolio. A window of M consecutive minutes for N stocks goes in; for every minute and every stock the network predicts the next minute's log-return, and from the market state it predicts the next timestamp. Every stock goes through the same weights, so training and validation can use different companies and any N. Change the sizes below; shapes and parameter counts update. Equations for each layer are on the Mathematics page.

The three return distributions: Gaussian, Student-t and Huber
Gaussian — light tails. The loss is a parabola, so one extreme minute produces a huge gradient and a few outliers can dominate training. A move of 5 standard deviations is treated as essentially impossible.
Student-t — heavy tails (the default). The loss grows only like a logarithm, so outliers cost little, and the scale σ is learned per stock and minute. Small ν = heavier tails; as ν grows it becomes the Gaussian. Needs ν > 2 for a finite standard deviation.
Huber — a loss, not a fitted distribution: quadratic for small errors, then linear. Read as a density it is a Gaussian centre with exponential tails. It only fits the location; there is no σ, so it says nothing about uncertainty.
