The rules
Verbatim from TradingGameRules.txt (repo root) — the single source of truth every constant in constants.jl and every check in test_rules.jl traces back to. The cards below show the rule text; where a constant has since been tuned, the current value is noted. Rule 9 (the 1-day lock-up) was added after Stage 1 shipped and folded into the simulator and its test suite the same day.
1–2
Start with a configurable amount of cash. Initial portfolio value equals that starting cash exactly.
3
Buy and sell stocks on the NSE or BSE.
4
Sale proceeds go into reserved cash — counts toward portfolio value, but can't fund a purchase — for 2 trading days before becoming spendable cash.
5
Purchases are capped by available (non-reserved) cash.
6
Shares trade in whole-number counts only — no fractional shares.
7
Portfolio value = stock value (continuously changing) + cash + reserved cash.
8
Decisions only while markets are open, at most every 15 minutes — or immediately after a news release.
9
A position is force-sold after a maximum holding time, no exceptions. Now: 14 trading days under v1; v2 and v3 have no forced exit — a lot held 7+ days costs a soft penalty instead (off by default).
10
A bought lot can't be voluntarily sold again for 1 trading day.
11
Every buy or sell costs 0.5% of the transaction value in fees — deducted from cash on a buy, from proceeds on a sell.
added12
No single stock's holding may exceed a share of total portfolio value — enforced when buying, not by force-trimming later drift. Now 30%. Under v3 a buy that would exceed it is charged as an illegal move.
added13
At most N_MAX distinct stocks may be held at once. Now half the candidate universe (20 of 40).
14
Objective: continuously maximize total portfolio value.
added15
A stock that was sold can't be newly bought again for 7 trading days. Adding to a stock still held is exempt.
added16
Spendable cash above 30% of portfolio value is discouraged — a soft penalty, not a mask (v1: on by default; v2/v3: --cash-penalty, off by default).

Policy architecture
One joint decision per step across every candidate stock — not independent per-stock scores. ActorCriticPolicy, built entirely from Flux primitives already used elsewhere in this repo. Order inside a v2/v3 step: settle reserved cash → fill the action at the current close → advance the clock → settle again for the new date → mark value → reward (v2: log-return window minus penalties; v3: the ledger, paid when a reward window ends). The validation walk-through below follows v3 and notes where v1 differs.
Validation: one decision step
A validation run is the same rollout code as a training episode, run once every --eval-every iterations over the held-out date window with greedy=true: each candidate takes its single most-likely action instead of a sampled one, and nothing is learned. Its summed reward is val_return, which alone decides whether policy.bson is checkpointed. Below is exactly what runs for game v3, in order (v1 differences are noted). Rule numbers refer to constants.jl.
A · Once per validation episode — train.jl → ppo.jl → env.jl
1
train_policy!train.jl
When iter % eval_every == 0 it calls start_episode! (clears the live tracker, tags the phase val), then collect_rollout(env, policy, val_config; greedy=true, step_log=…, live_cb=…). The step_log is requested on every --val-steps-every-th run.
2
collect_rolloutppo.jl
Takes a CPU copy of the policy (single-bar forward passes are slower on GPU), calls reset!, and preallocates one observation tensor per bar for the whole episode (T decision bars) plus the per-step diagnostics log.
3
reset!env.jl
Cash ← initial cash; empties holdings, reserved cash, rebuy cooldowns and the penalty ledger; sets the first reward window (start value = initial cash); finds the first and last bar of the window; loads the validation candidate universe. v3 refuses a cache that isn't BSE 15-minute with a history axis.
B · Every 15-minute bar — the loop inside collect_rollout; one pass = one decision
1
assemble_observation!observation.jl
Writes the state at the current bar: per stock the 70 log-returns between the newest 71 completed hourly closes, plus the snapshot 100·ln(pnow/clast) from the last completed hourly close to this bar’s 15-min close; the holding state (held flag, unrealised %, remaining-hold fraction); four legality inputs per stock from legality_state (rebuy cooldown left ÷ 7, ln(cash / price·(1+fee)) as an affordability reading, headroom under the 30% position cap, sellable flag); and 7 portfolio ratios (cash, reserved, value/initial, stocks, cash ÷ cap, days over cap, free holding slots ÷ cap). (v1/v2: a 120-bar window, macro and news.)
2
sellable_maskaction.jl
For each stock: is there a lot that may be sold now (held and past the 1-day lock-up)? Where not, a SELL is impossible and its logit will be removed in the next step. Stored per step so PPO can replay it.
3
stack_observationsobservation.jl
Adds a batch dimension (B = 1) so the observation matches the network’s input shape.
4
policy(…) — ActorCriticPolicypolicy.jl
Per stock: the 70 returns + 8 state features + the 7 portfolio scalars (repeated) → one Dense 85→64 ReLU → one MultiHeadAttention pass over the N stock tokens → actor head gives 3 logits (HOLD/SELL/BUY) and 1 buy-weight logit per stock; the critic reads the mean attended token plus the portfolio scalars and gives V(s). An auxiliary legality head (Dense 64→4 on the same tokens) predicts, per stock, whether a buy would be refused for cooldown, cash, free slot or position cap; it does not affect the action or V(s) — its cross-entropy against the rules’ own answer (buy_blockers, stored per step) is added to PPO’s loss at weight 0.5, so the shared features are forced to carry the legality state.
5
mask_action_logits → softmax → argmaxaction.jl · ppo.jl
Impossible SELL logits are replaced by a large negative number, then softmax: the probabilities are conditional on the move being possible, and PPO’s log-probabilities use the same masked distribution. With greedy=true each candidate independently takes argmax. The buy weight is sigmoid(buy_weight_logit).
6
RawAction listppo.jl
One RawAction(sym_idx, kind, weight) per candidate is built and handed to step!.
7
step!env.jl
Dispatches to the same-bar path (v2/v3) and runs sub-steps 7a–7f, returning a StepResult(reward, done, info).
7a
_settle_reserved_cash!env.jl
Reserved-cash lots whose settlement date has arrived (sale + 2 trading days, rule 4) move into spendable cash, so settled cash is usable this bar.
7b
resolve_actionsaction.jl
Applies the rules to what the policy chose (see the list below). Every move it refuses or trims adds --illegal-penalty × the portfolio value at this moment to the window’s ledger; surviving BUYs are sized from the cash pool.
7c
_apply_actions!env.jl
Executes the surviving trades at this bar’s close. SELL: every lot of that symbol past the lock-up is sold (_execute_sell!). BUY: whole shares only, floor(notional / price), debits cash by notional + 0.5% fee and opens a new Holding.
7d
_advance_clock! + settleenv.jl
Moves to the next bar, settles reserved cash for the new date. (v1 advances first and fills at the next bar’s price, and runs a forced-exit step for lots held ≥ 14 days; v2/v3 have no forced exit.)
7e
portfolio_breakdownenv.jl
Value = stocks + cash + reserved, marked at the new bar. The cash-ceiling and overdue-hold penalties (--cash-penalty, --hold-penalty; off by default) are added to the ledger on this bar.
7f
rewardenv.jl
0 unless a reward window ends here (every --reward-window-days trading days, and the last bar). Then R = (V − Vstart)/Vstart − ledger/Vstart, and the ledger and Vstart reset. (v1/v2: _log_return_reward!, the weekly log(V / Vwindow start), minus the penalties each bar.)
8
_annotate_trade_probs!ppo.jl
Stamps each trade event of this bar with the actor’s p(hold)/p(sell)/p(buy) for that stock — the record of what the policy itself wanted.
9
record_step!step_log.jl
When the per-step log is on: writes this bar’s column — every stock’s probabilities (masked and unmasked SELL), the chosen actions, buy weights, V(s), the reward and its illegal-move part, the book — whether or not anything traded.
10
RolloutStep + live_cbppo.jl · live.jl
The step (observation, mask, action, log-probability, V(s), reward) is stored in the buffer. The live callback appends the bar to the tracker’s value curve and trade list and rewrites live_status.json every 5 bars.
C · After the last bar — back in train_policy!
1
val_return, val_valuetrain.jl
val_return = the sum of the window rewards over the episode (so it already has the penalties taken out — it is not the pure portfolio return); val_value = final portfolio value.
2
save_val_run!live.jl
Writes val_runs/iter_NNNNN.json (value curve, every trade, final holdings; never overwritten) and adds the run’s summary to val_runs/index.json. The live page’s charts read the index; the trades table fetches the run file on demand.
3
save_step_log / save_step_summarystep_log.jl
Writes val_steps/iter_NNNNN.bson (the full per-bar, per-stock log) and iter_NNNNN.json (a per-bar summary the live page reads to fill in the no-action rows).
4
checkpoint checktrain.jl
If val_return beats the best so far, the policy is saved to policy.bson. Training return never checkpoints when a validation window exists.
Masked before the policy samples — conditional probabilities, game v3
SELL
No lot of that stock may be sold now (not held, or every lot inside the 1-day lock-up, rule 10): its SELL logit is removed, so HOLD and BUY share the probability. Costs nothing — it can’t be chosen.
What resolve_actions refuses and charges — after the policy has chosen; v3 adds the charge
BUY · universe
Symbol not in this episode’s candidate list → ignored.
BUY · cooldown
Opening a new position in a stock sold within the last REBUY_COOLDOWN_DAYS (rule 15) → refused and charged. Adding to a stock still held is exempt.
BUY · holdings cap
If the portfolio already holds n_max_holdings(N) symbols (rule 13), new positions beyond the free slots are refused and charged — which ones get in is random (rollout RNG), not by list order.
BUY · no cash
No spendable cash, or not enough for even one share of that stock (rule 5, whole shares) → refused and charged. Same-bar sale proceeds and reserved cash are not spendable.
BUY · cash split
Surviving buys split the cash held at the start of this bar in proportion to their buy weights, net of the fee.
BUY · size cap
A buy that would take a stock over MAX_POSITION_FRACTION of the portfolio (rule 12) is charged; the part within the cap still fills. Cash freed by the cap is left unspent.
Things worth remembering
Timing
The policy sees bar t (the history up to the last completed hour, plus bar t’s 15-min close as the snapshot) and trades at bar t’s own close (v3). History bars enter only when complete, so nothing after the decision is visible. (v1 traded at bar t+1’s close.)
Penalties are paid late
Under the v3 reward an illegal move is added to a ledger and only deducted when the reward window ends; it is not felt on the bar it happens. Many windows (a short --reward-window-days) give PPO something to compare; one window per episode leaves every step with the same return.
Reward ≠ portfolio return
val_return subtracts the penalties, so it can be far below Vfinal/Vinitial − 1. The real return is in the run’s value curve.
All-at-once buying
Every candidate whose argmax is BUY is bought on the same bar, splitting the whole cash pool; with many BUYs most are over the position cap or short of a share and are charged.
Greedy ≠ training
Training samples from the probabilities, so exploration can try SELL even when it is not the argmax. Validation never does — a policy that never ranks SELL first will never sell in validation, whatever training saw.

Does it actually learn? — mechanics check (v1, synthetic)
An 80-iteration PPO run on a synthetic scenario — one stock trending strongly up, one down, one flat over a 40-trading-day window — so "buy and hold the winner" is a clearly optimal, learnable policy. A policy that had learned nothing would hover near zero. This is a mechanics sanity check on synthetic data with the original v1 game, not a real-market backtest, and it was run before game v2/v3 existed. Status on real data: an NSE v2 run with --entropy 0.2 stayed at uniform action probabilities (the entropy bonus dominated); a BSE v3 run has not been trained at scale yet. Open items
●
A full v3 training run
Everything is built and unit-tested, and short runs on real BSE data work, but no multi-year v3 run has been studied yet. Expect a random policy to be dominated by illegal-move penalties early on; a smaller --illegal-penalty or shorter --reward-window-days are the first knobs.
●
Credit assignment under windowed rewards
The v3 reward arrives once per window. With one episode per PPO update the advantage is mostly R − V(s); several shorter episodes per update (or short windows) would give the baseline more to compare.
●
Thin BSE stocks
Most BSE small caps barely trade, so their 15-minute bars are largely forward-filled and not realistically tradable at those prices; build the cache with --min-mcap. A proper liquidity filter on the universe is not built.
●
News and macro for v3
Switched off in v3 to simplify (code kept; v1/v2 still use them). News is NSE-only: news_features.jl reads NSE announcements keyed by NSE symbols and 1-minute snapshots from the NSE tree.
●
Live execution
Explicitly out of scope. StockSwingPredictor/broker.jl is read-only (holdings, positions, margins, orders) — no order-placement function exists anywhere in this repo yet.
